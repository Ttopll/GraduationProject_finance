# 基于规则引擎的家庭财务管理系统的设计与实现

## 摘要

随着移动支付、网络消费和家庭多成员共同支出的普及，家庭财务数据呈现出来源分散、记录频繁、结构复杂等特点。传统手工记账方式依赖用户主动维护，容易出现漏记、分类不统一、预算风险发现滞后等问题。针对上述情况，本文设计并实现了一套基于规则引擎的家庭财务管理系统。系统以家庭为基本管理单位，围绕用户认证、家庭成员管理、账户管理、收支分类、交易流水、预算管理、规则预警、通知提醒和真实数据分析等功能展开，实现了从数据录入、预算统计、规则评估到通知生成的业务闭环。

系统采用前后端分离架构。后端基于 Spring Boot、Spring Data JPA、Spring Security、MySQL 和 JWT 实现，负责业务接口、数据持久化、权限校验和规则评估；管理员端采用 Vue3 实现，用于管理基础业务数据、维护规则通知和展示真实数据分析结果；小程序端面向家庭用户，提供账户、交易、预算、通知和个人中心等移动端功能。系统规则引擎支持单点阈值、连续超阈和趋势异常等规则类型，可根据家庭总支出、分类支出和预算使用情况触发站内通知。为增强系统的数据支撑能力，项目还引入 Online Retail、World Bank 和 FRED 等真实数据来源，完成数据清洗、导入和分析接口展示。

测试结果表明，系统能够完成用户登录、家庭上下文建立、业务数据维护、预算使用率计算、规则评估、通知生成和真实数据分析等核心流程，基本满足家庭财务管理系统的设计目标。

关键词：家庭财务管理；规则引擎；预算预警；Spring Boot；Vue3；微信小程序

## Abstract

With the popularity of mobile payment, online consumption and multi-member household spending, household financial data has become increasingly scattered, frequent and complex. Traditional manual bookkeeping relies heavily on users' active input and is prone to missing records, inconsistent categories and delayed budget risk detection. To address these problems, this thesis designs and implements a household financial management system based on a rule engine. The system uses family as the basic management unit and provides functions such as user authentication, family member management, account management, category management, transaction records, budget management, rule-based alerts, notifications and real-data analysis.

The system adopts a front-end and back-end separation architecture. The backend is implemented with Spring Boot, Spring Data JPA, Spring Security, MySQL and JWT, providing business APIs, data persistence, access control and rule evaluation. The administrator web application is implemented with Vue3, supporting business data management, rule and notification management and real-data analysis display. The mini program is designed for household users and provides mobile functions such as accounts, transactions, budgets, notifications and profile. The rule engine supports threshold, consecutive threshold and trend anomaly rules, and can generate in-system notifications according to family expenses, category expenses and budget usage. In addition, real datasets from Online Retail, World Bank and FRED are introduced to support data import and analysis.

The test results show that the system can complete key workflows including login, family context creation, business data maintenance, budget usage calculation, rule evaluation, notification generation and real-data analysis, which basically meets the design objectives of the household financial management system.

Keywords: household financial management; rule engine; budget alert; Spring Boot; Vue3; WeChat mini program

## 第一章 绪论

### 1.1 设计背景及意义

家庭财务管理是个人和家庭日常生活中的重要内容。随着移动支付和线上消费场景的普及，家庭成员可能同时通过现金、银行卡、支付宝、微信、信用卡等不同渠道完成收入和支出操作。财务数据来源不断增加，使家庭难以及时掌握整体收支状况、预算执行情况和潜在风险。如果长期缺少统一管理，容易出现消费结构不清、预算失控、债务提醒不及时等问题。

传统记账方式主要依赖用户手工记录，适合处理少量数据，但面对多账户、多成员、多分类和持续性消费时维护成本较高。部分记账工具虽然能够提供基本流水记录和图表展示，但对家庭协同、规则化预警和多端联通支持不足。用户往往需要主动查看预算页面才能发现超支情况，系统缺少主动提醒能力。

基于上述背景，本文将规则引擎思想引入家庭财务管理系统。系统不仅能够记录家庭财务数据，还能够根据预设规则对预算和支出进行判断，在出现预算风险时生成通知提醒。该设计能够提高家庭财务管理的自动化程度，也能体现毕业设计在业务建模、后端开发、前端联通和数据分析方面的综合实现能力。

### 1.2 研究现状

目前个人财务管理系统主要包括移动记账软件、支付平台账单系统和综合理财平台。移动记账软件通常操作简单，支持日常收支记录和分类统计，但部分系统对家庭多成员协同支持不足。支付平台账单系统能够自动保存本平台消费记录，但数据局限于单一平台，无法统一管理其他账户。综合理财平台功能较丰富，能够进行资产分析和投资建议，但系统复杂度较高，普通家庭日常使用存在一定成本。

在技术层面，规则引擎常用于风控、审批、监控告警和推荐系统等场景。其核心思想是将业务判断条件抽象为可配置规则，系统根据规则动态执行判断和动作。对于家庭财务管理系统而言，预算超支、连续高支出、分类支出异常等场景都适合用规则进行描述。本文没有采用复杂商业规则引擎，而是结合毕业设计规模，实现轻量级规则定义与评估机制，使系统能够满足预算预警和通知生成需求。

## 第二章 相关理论与技术

### 2.1 家庭财务管理系统概述

家庭财务管理系统的核心目标是帮助家庭统一管理收入、支出、账户、预算、债务和资产信息。与个人记账不同，家庭财务管理需要考虑多成员协作和数据隔离问题。系统通常需要以家庭为单位组织数据，并对不同家庭之间的数据进行隔离。

本系统以家庭作为核心业务边界。用户登录后通过家庭成员关系确定可访问的家庭数据。账户、分类、交易、预算、规则和通知均绑定家庭 ID，从而保证业务数据的一致性和安全性。

### 2.2 规则引擎基本思想

规则引擎是一种将业务规则与业务流程相对分离的设计思想。规则通常由条件和动作组成：条件用于判断某种业务状态是否成立，动作则定义条件成立后系统应执行的操作。在家庭财务管理场景中，规则条件可以是“餐饮支出超过 3000 元”或“连续三个月家庭总支出超过阈值”，动作可以是“生成通知提醒”。

采用规则引擎的优势在于提升系统扩展能力。当预警条件变化时，系统可以通过调整规则配置实现，而不需要频繁修改核心业务代码。本文实现的规则引擎属于轻量级规则引擎，重点满足毕业设计中的预算预警、支出异常和通知触发需求。

### 2.3 Spring Boot 技术

Spring Boot 是 Java Web 开发中常用的快速开发框架，能够简化 Spring 项目的配置和部署。系统后端基于 Spring Boot 构建 REST API，通过 controller 层接收请求，service 层处理业务逻辑，repository 层访问数据库。Spring Boot 的自动配置机制降低了项目搭建难度，提高了开发效率。

### 2.4 Spring Security 与 JWT

系统采用 Spring Security 进行安全控制，并使用 JWT 保存登录状态。用户登录成功后，后端生成 Token 返回给前端。前端后续请求在请求头中携带 Token，后端通过过滤器解析 Token 并构建当前登录用户上下文。该方式适合前后端分离项目，能够避免传统 Session 对服务端状态的依赖。

### 2.5 Vue3 与微信小程序

Vue3 用于实现管理员端页面。管理员端主要负责业务数据管理、规则通知管理和真实数据分析展示。Vue3 的组件化特性能够提升页面复用性，使后台页面更容易维护。

微信小程序端面向普通家庭用户，适合移动端轻量化使用场景。用户可以在小程序中查看家庭首页、账户、交易、预算和通知等信息，与管理员端共同调用后端接口，实现两端联通。

### 2.6 MySQL 与 Spring Data JPA

MySQL 用于保存系统业务数据。Spring Data JPA 用于简化数据库访问，通过 repository 接口完成常见增删改查操作。系统中的用户、家庭、账户、分类、交易、预算、规则、通知和真实数据表均通过 JPA 实体与数据库表建立映射。

### 2.7 本章小结

本章介绍了家庭财务管理系统、规则引擎、Spring Boot、JWT、Vue3、微信小程序、MySQL 和 Spring Data JPA 等相关理论与技术。这些技术共同构成了系统实现的基础。

## 第三章 规则引擎与真实数据分析设计

### 3.1 规则引擎总体设计

系统规则引擎围绕规则定义、规则评估、执行日志和通知生成四个部分展开。规则定义用于保存规则的基本信息和判断条件；规则评估负责读取规则并计算业务指标；执行日志用于记录规则命中情况；通知生成用于将规则结果反馈给用户。

规则评估流程如下：

1. 根据家庭 ID 查询启用状态的规则。
2. 根据规则类型和指标类型查询对应交易或预算数据。
3. 计算当前周期支出、分类支出、预算使用率或历史趋势。
4. 使用比较符和阈值判断规则是否命中。
5. 若规则命中，写入执行日志并生成通知。

### 3.2 规则定义模型

规则定义主要包括规则名称、规则类型、指标类型、时间范围、比较符、阈值、关联分类、动作类型、提示模板和优先级等字段。规则类型用于区分单点阈值、连续超阈和趋势异常。指标类型用于区分家庭总支出和分类支出。时间范围用于确定统计周期。比较符和阈值共同决定规则判断条件。

### 3.3 单点阈值规则

单点阈值规则用于判断某个统计周期内的金额是否超过固定阈值。例如，若某家庭当月餐饮支出超过 3000 元，则系统生成餐饮支出提醒。该规则逻辑简单，适合预算预警和基础消费控制。

### 3.4 连续超阈规则

连续超阈规则用于判断多个连续周期内是否持续超过阈值。例如，若家庭连续三个月总支出均超过 6000 元，则说明家庭支出水平可能长期偏高。该规则相比单点阈值更关注持续性风险。

### 3.5 趋势异常规则

趋势异常规则用于判断当前周期数据相对历史均值是否出现明显增长。例如，若本月餐饮支出比前两个月平均值增长超过一定比例，则系统可认为该分类存在异常增长。该规则能够发现不一定超过固定预算但变化较明显的消费行为。

### 3.6 真实数据分析设计

系统引入真实数据分析模块，主要用于增强项目数据支撑和答辩展示能力。项目使用的真实数据包括 Online Retail 零售交易数据、World Bank 家庭消费数据和 FRED 宏观经济序列数据。数据通过脚本抓取和清洗后保存到 `data/processed` 目录，再由后端接口导入数据库。

真实数据分析模块提供导入接口、零售交易概览接口、国家消费趋势接口、宏观经济序列接口和答辩摘要接口。管理员端可调用这些接口展示交易结构、国家趋势和宏观数据情况。

### 3.7 本章小结

本章重点介绍了系统规则引擎和真实数据分析模块的设计。规则引擎用于实现预算预警和通知闭环，真实数据分析用于提升系统的数据展示和分析能力。

## 第四章 系统需求分析与总体设计

### 4.1 系统需求分析

系统需要满足家庭财务管理的基本业务需求，包括用户登录、家庭管理、账户管理、分类管理、交易流水、预算管理、规则预警、通知提醒、真实数据分析和多端展示。

管理员端需要支持业务数据维护、规则通知管理、真实数据导入分析和系统状态查看。小程序端需要支持普通用户查看家庭财务数据、维护账户交易、查看预算和接收通知。

### 4.2 非功能需求分析

系统应具备基本安全性，所有受保护接口需要在用户登录后访问。系统应具备数据隔离能力，不同家庭之间的数据不能相互访问。系统应具备可维护性，后端按照 controller、service、repository、entity、dto 和 security 分层组织代码。系统还应具备可演示性，能够通过管理员端、小程序端和接口测试展示完整业务流程。

### 4.3 系统总体架构设计

## 第五章 系统实现

### 5.1 用户认证与权限控制实现

系统通过 `AuthController` 和 `AuthService` 实现登录认证。用户提交用户名和密码后，系统校验用户信息并生成 JWT。前端在后续请求中携带 Token，后端通过安全过滤器解析 Token 并识别当前用户。

家庭访问权限通过家庭成员关系控制。业务接口在处理家庭数据时，会校验当前用户是否属于该家庭，从而保证家庭之间的数据隔离。

### 5.2 家庭与成员管理实现

家庭模块通过 `FamilyController` 和 `FamilyService` 实现。用户可以创建家庭，也可以通过邀请码加入家庭。创建家庭时，系统会自动将创建者写入家庭成员表，并赋予家庭所有者身份。家庭上下文建立后，系统后续业务数据均与家庭 ID 绑定。

### 5.3 账户、分类与交易实现

账户模块用于维护银行卡、现金、支付账户等资金账户。分类模块用于维护收入和支出分类。交易流水模块通过 `TransactionRecordController` 和 `TransactionRecordService` 实现，支持收入、支出和转账记录。

创建交易时，系统会根据交易类型更新账户余额。支出交易减少账户余额，收入交易增加账户余额，转账交易同时影响来源账户和目标账户。交易数据会进一步参与预算统计和规则评估。

### 5.4 预算管理实现

预算模块通过 `BudgetController` 和 `BudgetService` 实现。用户可以为指定分类设置月度预算和预警比例。系统根据预算周期统计对应交易金额，计算预算使用率。当使用率达到预警比例或超过预算金额时，预算会被识别为风险预算。

### 5.5 规则与通知实现

规则模块通过 `RuleDefinitionController`、`RuleDefinitionService` 和 `RuleEvaluationService` 实现。系统读取启用规则后，根据规则配置查询交易或预算数据，计算指标并判断是否命中。若规则命中，系统写入规则执行日志，并通过 `NotificationService` 生成通知。

通知模块支持通知查询、标记已读、批量已读和删除已读通知。管理员端和小程序端均可以查看通知，从而形成规则触发后的反馈闭环。

### 5.6 真实数据分析实现

真实数据分析模块通过 `RealDataAnalysisController` 和 `RealDataAnalysisService` 实现。系统支持将清洗后的真实数据从 `data/processed` 目录导入数据库，并提供零售交易概览、World Bank 国家消费趋势、FRED 宏观序列和答辩摘要接口。

该模块可以展示真实交易数据的国家分布、消费趋势变化和宏观序列情况，为项目提供更具体的数据分析内容。

### 5.7 管理员端实现

管理员端使用 Vue3 实现，主要页面包括登录页、总控台、真实数据分析、用户与家庭、业务数据管理、资产与负债、导入导出、账单解析规则、规则与通知和系统说明。管理员端采用标准后台页面风格，主要通过表格、筛选栏、统计条和弹层表单展示功能。

规则与通知页面展示预算风险、规则覆盖、规则管理和通知中心。真实数据分析页面展示数据导入、零售概览、国家趋势和宏观序列结果。

### 5.8 小程序端实现

小程序端面向家庭用户，页面包括登录、首页、账户、账户表单、交易、交易表单、预算、预算表单、通知、个人中心和家庭信息。用户可以通过小程序查看家庭财务基础信息，维护账户和交易，查看预算执行情况，并接收系统通知。

### 5.9 本章小结

本章介绍了系统主要功能实现，包括认证权限、家庭管理、账户分类、交易预算、规则通知、真实数据分析、管理员端和小程序端。系统已形成从后端接口到两端页面的基本联通。

## 第七章 总结与展望

### 7.1 总结

本文设计并实现了一套基于规则引擎的家庭财务管理系统。系统以后端服务为核心，结合 Vue3 管理员端和微信小程序端，实现了用户认证、家庭管理、账户分类、交易流水、预算管理、规则评估、通知提醒和真实数据分析等功能。系统通过家庭上下文实现数据隔离，通过规则引擎实现预算风险自动识别和通知生成。

从实现结果看，系统已经形成较完整的业务闭环：用户登录后建立家庭上下文，维护账户、分类、交易和预算数据，系统根据预算和规则进行评估，并在规则命中后生成通知。管理员端用于系统管理和分析展示，小程序端用于普通用户移动端使用，真实数据分析模块则增强了项目的数据支撑能力。

### 7.2 展望

后续系统仍可从以下方面继续完善。首先，规则引擎可以支持更复杂的组合条件、规则分组和规则冲突处理。其次，通知模块可以接入微信订阅消息、短信或邮件推送。第三，前端页面可以进一步增强图表分析和交互体验。第四，可以增加更多自动化测试和异常场景测试，提高系统稳定性。最后，真实数据分析模块可以扩展更多统计指标和可视化图表，使系统分析能力更加完整。
