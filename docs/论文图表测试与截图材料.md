## 二、系统总体架构图说明

### 图名

图 3-1 系统总体架构图

### 图中元素

- 管理员端 Vue3
- 微信小程序端
- Spring Boot 后端服务
- MySQL 数据库
- 真实数据文件
- 数据采集与清洗脚本

### 图中关系

管理员端和小程序端都通过 HTTP 请求访问 Spring Boot 后端接口。后端负责登录认证、家庭权限校验、业务逻辑处理、规则评估和真实数据分析。业务数据和真实数据统一保存到 MySQL 数据库中。真实数据先由脚本抓取和清洗，再通过导入接口写入数据库。

### 可放入论文的说明文字

系统采用前后端分离架构。管理员端主要用于业务数据维护、规则通知管理和真实数据分析展示，小程序端主要面向家庭用户提供移动端使用入口。后端服务统一提供 REST API，并通过 JWT 完成用户认证，通过家庭成员关系完成数据权限隔离。MySQL 数据库用于保存用户、家庭、账户、分类、交易、预算、规则、通知以及外部真实数据。该结构能够保证多端共用同一套业务逻辑和数据来源。

## 四、规则引擎流程图说明

### 图名

图 3-3 规则引擎执行流程图

### 流程步骤

1. 用户在管理员端创建或启用规则。
2. 系统根据家庭 ID 查询启用规则。
3. 规则评估服务读取交易、预算和分类数据。
4. 系统根据规则类型计算指标。
5. 系统根据比较符和阈值判断规则是否命中。
6. 若命中，写入规则执行日志。
7. 调用通知服务生成站内通知。
8. 管理员端和小程序端展示通知结果。

### 可放入论文的说明文字

规则引擎是本系统的核心特色。系统通过规则定义表保存规则名称、规则类型、指标类型、时间范围、比较符、阈值和通知模板等信息。执行规则评估时，系统先读取当前家庭下启用的规则，再根据规则类型查询交易或预算数据并计算指标。当指标满足规则条件时，系统写入执行日志并生成通知。该流程实现了从财务数据到风险提醒的自动化闭环。

## 五、两端联通流程图说明

### 图名

图 4-1 管理员端与小程序端联通流程图

### 流程步骤

1. 用户在管理员端或小程序端登录。
2. 后端返回 JWT 和家庭成员关系。
3. 前端保存 Token，并确定当前家庭 ID。
4. 管理员端维护账户、分类、预算和交易。
5. 小程序端读取同一家庭下的数据。
6. 管理员端执行规则评估。
7. 后端生成通知。
8. 小程序端通知中心展示通知。

### 可放入论文的说明文字

管理员端和小程序端没有各自维护独立数据，而是共同调用同一套后端接口。用户登录后，系统会返回家庭成员关系，前端根据当前家庭 ID 查询业务数据。管理员端新增的账户、交易、预算等数据会保存到数据库，小程序端再次查询时即可读取到相同数据。规则评估生成的通知也保存在后端通知表中，因此两端都可以展示同一套通知结果。
