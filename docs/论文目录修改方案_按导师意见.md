## 第2章 系统开发技术

### 2.1 Spring Boot 在后端业务接口中的应用

不要写“Spring Boot 是什么”。应写：

- 为什么本系统选择 Spring Boot。
- 用户认证、家庭账本、收支流水、预算管理、资产负债、理财建议、规则预警等接口为什么适合用 Spring Boot 组织。
- Controller、Service、Repository 分层如何帮助系统把业务逻辑和数据访问分开。

### 2.2 MySQL 与 Spring Data JPA 在财务数据持久化中的应用

重点写：

- 家庭财务系统需要长期保存用户、家庭、账户、分类、交易、预算、资产、债务、规则、通知、真实数据。
- MySQL 用于保证结构化数据存储。
- Spring Data JPA 用于降低增删改查代码量，让开发重点放在业务逻辑、预算统计、规则判断和数据分析上。

### 2.3 JWT 与权限控制在家庭数据隔离中的应用

重点写：

- 系统有管理员端和小程序端，两端都需要登录。
- JWT 用于前后端分离场景下传递用户身份。
- 家庭成员关系用于隔离不同家庭的数据，防止用户访问其他家庭的账户、交易和预算。

### 2.4 Vue3 在管理员端财务管理页面中的应用

重点写：

- 管理员端需要表格化管理账户、分类、预算、交易、资产、债务、规则和通知。
- Vue3 适合构建单页后台系统，配合组件化表格、弹层表单和状态管理完成后台操作。
- 管理员端不是系统核心本身，而是展示和维护核心财务数据的入口。

### 2.5 微信小程序在家庭用户端中的应用

重点写：

- 小程序端面向普通家庭成员，承担移动端查询、录入和通知查看。
- 小程序和管理员端共用同一套后端接口和数据库，体现两端联通。

### 2.6 CSV 数据处理与真实数据导入技术

重点写：

- 系统使用外部真实数据验证数据处理能力。
- Online Retail、World Bank、FRED 经过抓取、清洗、导入到数据库。
- 这些数据不是单独作为一章写，而是服务于后续“消费数据分析模块”和“系统测试”。

## 三、关于“核心技术是否完成”的判断

当前项目可以支撑论文核心技术描述，但要注意表达强度。

### 可以明确写“已实现”的内容

- 基于 Spring Boot 的家庭财务后端接口。
- 基于 JWT 的登录认证和家庭数据隔离。
- 家庭账本数据管理：账户、分类、交易、预算。
- 固定资产、债务、净资产等资产负债管理。
- 基于规则配置的预算预警和消费风险提醒。
- 通知生成和两端查看。
- 账单导入、解析规则和待处理账单。
- 家庭财务画像与基础理财建议。
- 外部消费数据导入和分析展示。
- 管理员端与小程序端共用后端数据。

### 需要谨慎写“基础实现”的内容

- 理财建议：当前更偏规则化建议，不是复杂智能推荐算法。
- 趋势分析：当前有基础统计和外部数据趋势，不是复杂预测模型。
- 规则引擎：当前是自研轻量规则引擎，不是 Drools 这种工业规则平台。
- 真实数据分析：重点是导入、统计、展示，不是机器学习建模。

### 不建议夸大的内容

- 不要写“智能投资推荐系统”。
- 不要写“高精度消费预测模型”。
- 不要写“商业级权限管理平台”。
- 不要写“完全自动化财务顾问”。
